# DISPOSITION.md: reusable components in Lane E scope

Format: legacy application doctrine disposition table (one row per reusable component). **Every verdict is a recommendation only. Nothing is retired, shut down, migrated or mutated by this audit.** Any physical retirement needs a separate authorised work order. The objective is the strongest GOLD MVP architecture, not maximum reuse. FALCON stays evidence-only and non-blocking whatever the verdict. Adjudication of verdicts is for CA/PO after the independent verdict (`VERDICT.md`, pending).

**Cost unit and basis.** Engineer-days (ED), order of magnitude, ESTIMATES made by this audit from counted artefacts (28 schemas and fixtures, 31 stale rows, 3-method sink interface, 5 identity inputs) and the amount of rework in EP-3 to EP-8. They are not measurements and not commitments. "Reuse" = use as is; "Refactor" = change in place; "Clean build" = start the component again to the same acceptance.

Criteria key used in the evidence column: AF architecture fit, CQ code quality, DET determinism, TE test evidence, MNT maintainability, CON contracts, OPS operational dependencies, IC integration cost.
